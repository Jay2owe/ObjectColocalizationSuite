# Fiji smoke test

Checks that the built plugin jar loads in a real Fiji, registers both menu
commands, and runs end to end from headless macros and from a headless Groovy
script. Everything it needs is generated by `make-fixtures.ijm`; no image data
is stored in the repository.

## Run

Use a throwaway copy of Fiji: the script replaces any
`Object_Colocalization_Suite-*.jar` in its `plugins/` folder with the one just
built.

```bash
./mvnw clean verify
cp -r /path/to/Fiji.app /tmp/fiji-smoke
bash scripts/fiji-smoke/run-smoke.sh /tmp/fiji-smoke /tmp/ocs-smoke-work
```

The optional third argument sets the log folder (default `<work>/logs`). Each
launch writes `<prefix>-<name>.log` (standard output) and `<prefix>-<name>.err.log`
(standard error); the prefix is `ocs-smoke` unless `SMOKE_LOG_PREFIX` is set.
Each launch is killed after `SMOKE_TIMEOUT` seconds (default 600).

It prints one line per check and exits non-zero if any fails:

| Check | What it proves |
|---|---|
| `fixtures` | the synthetic 2D and 3D label images, intensity images, `.roi` region and batch folder were written |
| `commands` | `Object Colocalization Suite` and `Batch (folder)` are registered to their classes |
| `quick-look`, `object`, `intensity`, `spatial`, `discovery` | each shipped preset runs from a macro line with `hide_display` and `output=`, writing the output tree, `run-record.json` and `README.txt` |
| `all` | `methods=all discovery` with intensity images and a region |
| `3d` | a 3D pair |
| `titles` | channels named by open window titles rather than paths |
| `batch` | `Batch (folder)` finds two fields by file name, passes `sweep_width=` through to each, and writes one run record per field |
| `api` | `OCS.run` from a headless Groovy script |
| `errors` | a bad option (`permutations=0`) and an impossible save folder each stop with their message and no stack trace |
| `... exit code 0` | Fiji exited cleanly |

The script also writes `digests.txt`: a SHA-256 of every output file, by path.
Outputs are deterministic, so two runs in the same work folder can be compared
file by file.

### Alongside the sibling plugins

The suite ships its own relocated copies of the cores it shares with
Centre-Particle Coincidence, Volumetric Colocalization, Object Territories and
Object Proximity Analysis. To check they coexist, run once as above, copy the
siblings' release jars into the same Fiji's `plugins/`, and run again into the
same work folder with

```bash
SMOKE_SIBLINGS="cpc volcoloc territories proximity" \
    bash scripts/fiji-smoke/run-smoke.sh /tmp/fiji-smoke /tmp/ocs-smoke-work /tmp/ocs-smoke-logs-2
```

which also runs one command of each sibling (`sibling-<name>` checks). The two
`digests.txt` files must be identical.

## Notes

- The Windows launcher (`fiji-windows-x64.exe`) writes its console output only
  when standard output is a file handed to it directly; under `timeout` it
  prints nothing, so the script uses a watchdog instead.
- Headless, a refused option ends the macro with `Macro Error: <message>` on
  standard error.
- The ROI Manager needs a display, so the fixtures use a `.roi` region; reading
  `.zip` ROI sets is covered by the unit tests.
